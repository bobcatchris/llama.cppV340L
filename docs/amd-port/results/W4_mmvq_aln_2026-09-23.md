## WHY: GCN y-operand economics

get_int_aln loads uint4 (16 B) to extract one dword lane. On gfx900 the
hardware decomposes a dwordx4 into per-dword loads, so per sub-block the aln
path issues 4x the y-operand load instructions to use 1 lane, plus lane
extract ALU and register pressure; the legacy path loads exactly the dword it
needs and the wave-level coalescer already covers the 32 B block. The rpb=1
clone had a different occupancy/instruction mix where the saved scalar-load
count outweighed this; the real rpb=2 schedule does not. Consistent with the
W3 ceiling statements: the K-quant residuals after share are operand-traffic
bound, and aln ADDS traffic-class work.

## Producer design (shipped, default OFF)

quantize_q8_1 templated on aln (ggml/src/ggml-cuda/quantize.cu). aln=false is
the shipped kernel, byte-identical. aln=true DUAL-emits: legacy 36 B region at
+0 (every consumer type keeps reading valid values whatever its gate) plus the
48 B block_q8_1_aln region (ds@0, pad, qs@16) behind it for the aln-gated T=4
share arms. Values identical in both regions; only store addresses differ.
Measured emit cost (clone bench, K=5120 T=4, 640 blocks, 200 iters x 5 reps):
legacy 4.22 us, dual 4.35 us (+3.0%, ~0.13 us once per src1 per compute; the
q81 act cache amortizes it across ffn_up/ffn_gate). A separate transform pass
would add a launch plus a full 36 B read + 48 B write - strictly worse than
the +0.13 us dual store, so dual-emit wins the mission's "measure which is
cheaper" question by inspection and measurement.

Consumer: the six T=4 share arms read the aln region through the exact
*_apply_aln twins in vecdotq.cuh (get_int_aln uint4 operand loads); all other
types and all T != 4 arms read the legacy region unchanged. Gate: single env
LLAMA_MMVQ_ALN=1 computed once at the buffer (mmvq_aln = env && !ids &&
ne11 == 4) and threaded to both sides; unset = byte-identical everywhere.

## Oracle defect found and closed (can-fail-before-can-green)

The v1 wiring emitted the aln layout as the ONLY layout of the shared T=4
buffer. The device oracle caught it immediately: iq4_xs (no aln twin, share
kept OFF) read the aln bytes as legacy - dst mismatch at the first float of
the iq4_xs T=4 slot. This is exactly the mission's warned producer/consumer
mismatch class: ONE src1 buffer feeds matmuls of DIFFERENT weight types, so a
single-layout producer can never be type-safe. Fix = dual-region emit (above).
A cache-key layout field (common.cuh key.layout, default 0) additionally keeps
legacy and dual buffers in separate cache slots so a cross-layout hit can
never happen (extended test_q81_cache_host covers it).
