Reading:

1. RCCL-F32 beats the butterfly 2.2-2.6x at EVERY size, including the real
   prefill size (5.48 ms vs 13.17 ms, -7.69 ms/boundary). The butterfly's
   5 host-staged transfers x 10 MiB dominate; pinned staging recovers only
   ~6%. Gate-extend is justified on the bench.
2. RCCL-BF16 is still 1.90x faster than RCCL-F32 at 10 MiB (2.87 vs
   5.48 ms): the effective SHM wire is ~2.5 GB/s at both dtypes, so time
   tracks wire bytes (fp32 ring moves 2 x (n-1)/n x S; bf16 half that).
   Conversions are noise at these sizes.
3. Scaling continuity vs E-085 (32 KB: 94.0 us) holds: 80 KB -> 126.5 us.
   A second clean boot reproduced the 512 KB cell within 1.3%
   (361.5/350.5 vs 356.9/342.2). A run interleaved with 16-way compile
   load showed inflated AVGS (host enqueue contention) with intact MINS -
   it is voided as session of record; do not bench while building.
4. Modeled served prefill impact of the fp32 gate: +2.61 ms per boundary
   vs today's bf16 branch. At the E-078/E-085 structure (~24 cut points
   per full target pass, ~48 boundaries per decode round) that is ~+63 ms
   per 512-token chunk (~6.2 s at the 82 tok/s 8k cell) = ~+1% prefill
   wall; worst case at 2 cuts/layer x 65 layers it would be ~+5.5%. The
   served prefill guard cell arbitrates. Decode is untouched (below the
   threshold either way). VS the butterfly default the fp32 gate is a
   -7.69 ms x boundaries WIN (2.4x), i.e. ~-185 ms/chunk modeled at ~24
   boundaries.

## 3. NUMERICS (same boot, probe section 2)

vs the butterfly fp32 grouping ((r0+r2)+r1), host reference, uniform
[-1,1] inputs; seeds 64 (16 at the 10 MiB size):

- RCCL-F32: 0 seeds byte-identical (expected, sum-order reorder, the
  SIGNED-OFF class); rank0 mismatched elements 4.18% / 4.57% / 4.63%
  (20480 / 262144 / 2621440), max ULP 128 / 512 / 512 - bounded dust,
  same profile as the decode class E-085 measured at 32/128 KB.
  Cross-rank identical 64/64 and 16/16 (replica consistency preserved).
- RCCL-BF16 (today's served prefill branch): 0/64 seeds, ~99.998% of
  elements differ, max ULP 3.15e9, max relative error 3.3e4 at
  cancellation sites (bf16 mantissa loss on near-zero sums). This is a
  DIFFERENT and much wider class than the sign-off text names. It does
  not move the served gates (E-090/E-094 batteries passed on it), but it
  is not "bounded dust" and should not be described as such.

Determinism pin: RCCL's algo/proto choice is size- and env-dependent.
Two attempts to capture RCCL_DEBUG=INFO from the desk runner produced no
debug lines (env not seen by librccl through this shell chain); the
small-tensor class fingerprint of record remains the verify-transport
capture (results/rccl_probe_transport2_20260922_174701.txt: every channel
via SHM/direct/direct, 2 channels, ring + tree). The prefill-class
connect-line fingerprint must be captured in the served window (one INFO
boot), per the E-085 convention; drift there changes the numerics class
silently.

Prefill-dump consequence (explicit, per mission): the tile desks'
bit-exact prefill dumps WILL change class under the extended gate -
fp32-ring sum order replaces the bf16-compress output (or the butterfly
grouping on unset arms). Their gates must be re-stamped against the
served arm's class, not treated as failures.

## 4. IMPLEMENTATION (env-gated, unset = today's behavior)

ggml/src/ggml-cuda/ggml-cuda.cu, small hunks around the existing comm code.
FINAL DESIGN (desk resumption): the rescued WIP's GGML_RCCL_FP32 bool is
superseded by a three-way size-class gate so the owner picks the prefill
class - RCCL-F32, RCCL-BF16, or butterfly - not just on/off:

1. comm context gains `ggml_rccl_prefill_class prefill_class` (UNSET / F32 /
   BF16 / BUTTERFLY) and `bool nccl_up` (set iff ncclCommInitAll succeeds).
2. ggml_backend_cuda_comm_allreduce_tensor: at prefill sizes
   (ne >= GGML_RCCL_PREFILL_NE = 131072) the gate routes - BUTTERFLY, or
   F32/BF16 without comms, returns false so the meta-backend butterfly runs
   (the init-failure fallback); everything else dispatches unchanged.
3. ggml_backend_cuda_comm_allreduce_nccl: at ne >= 131072 the gate picks
   fp32 vs bf16-compress directly; below the gate the upstream heuristic is
   untouched (per-rank bands 32768 / 131072 / 262144).
4. comm_init parses GGML_RCCL_PREFILL (exact "f32" | "bf16" | "butterfly";
   unknown values warn and behave as unset), one INFO line when active, one
   WARN when an rccl class is named but the nccl path is not up.

Semantics:

- GGML_CUDA_ALLREDUCE unset (HIP default): butterfly at every size,
  byte-identical to today. GGML_RCCL_PREFILL=f32/bf16 is inert without the
  nccl path: prefill falls back to the butterfly with a WARN at init.
- GGML_CUDA_ALLREDUCE=nccl, GGML_RCCL_PREFILL unset: byte-identical to
  today's served behavior (fp32 < threshold, bf16-compress >= threshold).
- GGML_CUDA_ALLREDUCE=nccl GGML_RCCL_PREFILL=f32: fp32 ring at the prefill
  sizes (ne >= 131072). Numerics class = the signed-off sum-order dust ONLY;
  the bf16 prefill class is REMOVED while the gate reads f32. Bench cost:
  +2.61 ms/boundary vs bf16 (~+1% prefill wall modeled), zero decode cost;
  bench win vs butterfly: 2.4x at prefill sizes.
- =bf16: today's served prefill class, pinned explicitly (same bytes as
  unset at n=3; also overrides the fp32 bands of the n<=2 / n>=4 heuristic
  above the gate).
- =butterfly: full butterfly at the prefill sizes while decode keeps rccl -
  the byte-exact exit door without giving up the signed-off decode win.

Decode (ne < 131072) is byte-identical in every gate state.
