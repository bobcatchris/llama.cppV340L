## s3. Defect found and fixed (blocking)

The script defaulted `--batch-size 512 --ubatch-size 512` while the
of-record geometry after the E-148 ub1024 promotion is 1024/1024
(launch_tp3_200k.sh line 35; CAMPAIGN_DOSSIER.md 5.4). Fired as-is, the
window would have measured at the wrong geometry and a PROMOTE ratchet
would not have applied to the of-record launch. Fixed in place, 6 hunks:

1. `BATCH=${U2_BATCH:-512}` -> `BATCH=${U2_BATCH:-1024}` (+ E-148 comment)
2. `UBATCH=${U2_UBATCH:-512}` -> `UBATCH=${U2_UBATCH:-1024}`
3. header comment: `-c 200000 -b 512 -ub 512` -> `-b 1024 -ub 1024`
4. `u2_cell_py` argv slice `[1:12]` -> `[1:14]`, new trailing args
   `batch, ubatch` threaded from the cell call site (`"$BATCH" "$UBATCH"`)
5. PROVENANCE stamp: hardcoded `canonical-200k-512-512-q40kv` ->
   `canonical-200k-%s-%s-q40kv` from the actual batch/ubatch (stays
   truthful under any U2_BATCH/U2_UBATCH override)
6. dry-run plan: added `geometry: ctx/batch/ubatch` line so the geometry
   is visible at fire time

Post-fix: bash -n clean; both embedded python heredocs AST-parse clean;
`--dry-run` and `--dry-run --long` exit 0 and print
`geometry: ctx=200000 batch=1024 ubatch=1024`.
