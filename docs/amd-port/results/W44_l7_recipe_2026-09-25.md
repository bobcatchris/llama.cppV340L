## 3. THE RECIPE (ranked moves, ms-first)

Mechanics verified in this tree (tools/quantize/quantize.cpp +
src/llama-quant.cpp): `--tensor-type name=type` / `--tensor-type-file` take
REGEX patterns, applied with regex_search, FIRST match wins
(llama-quant.cpp:678-688); a tensor whose target type equals its current
type is copied bit-exact, not requantized (`quantize = cur_type != new_type`,
llama-quant.cpp:1146-1148); `--allow-requantize` is required because the
source is quantized (llama-quant.cpp:1215); IQ4_XS/Q4_K targets do NOT
require an imatrix (tensor_requires_imatrix, llama-quant.cpp:767-778), and
no imatrix file exists on disk anyway. There is no per-layer-index CLI, but
regex on `blk\.<n>\.` gives per-layer and per-class precision.

## 8. ONE-PARAGRAPH ANSWER TO THE MANDATE

The file has no q4_0 weights to lower; the fast lane is already 4-bit
(iq4_xs, 75 GB/s served = 7.08 ms/Gparam vs 8.49-23.71 for everything else),
and the schedule is byte-rate-bound enough that ms = bytes/rate arithmetic
transfers. The ms-optimal fit-free recipe is therefore byte-NEGATIVE: demote
the three slow-rate islands (output q6_K head 3.46 ms -> iq4_xs 1.17 ms,
+2.29; the 46 q5_K slices at 29 GB/s -> iq4_xs, +1.25; the GDN q4_K slices
-> iq4_xs which is literally smaller, +2.14) for +5.68 ms/cycle raw
(+1.2 to +4.6% served band, ~25.8 t/s), -71 MiB/die VRAM, one requant-down
build of ~93 tensors, gated by one ABBA acceptance window with the 0.02
absolute acceptance bar. "More layers at q4_0" is falsified unless an
unfunded q4_0 bench ever clears 66 GB/s; the bigger iq4_xs-everywhere prize
(+13 ms) is real arithmetic but is blocked by the 8 GiB/die envelope at
200k and by the missing f16 source, and it would be partially cashed anyway
by W37's Opp-1 schedule lift.
