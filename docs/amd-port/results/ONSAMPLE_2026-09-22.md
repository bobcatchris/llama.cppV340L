Date: 2026-09-22. Worktree wt-onsample, branch amd/onsample (synced onto
amd/v340-port-v2 @ 865e52cf1, fast-forward). Zero-GPU desk: implementation +

## 1. Design

The draft-mtp loop samples greedily: the drafted token is the top-1 of the
draft logits row. That row is vocab-axis sharded across the 3 serving dies
(output.weight AXIS_1 -> meta head result AXIS_0-disjoint) and materializes
on the host only through the spliced get: ~517 KB (129272 x f32) per draft
step, plus the full-vocab candidate build it feeds. E-065 proved backend
sampling under SPLIT_MODE_TENSOR aborts in
ggml_backend_meta_get_split_state (TOP_K/ARGSORT handle_per_row on AXIS_0;
the segment model cannot express an op whose output partition differs from
its input partition).

The design makes meta see a per-die unary pass:

- New op GGML_OP_ARGMAX_SHARD (ggml_argmax_shard(ctx, a)): output has the
  SAME shape/type as the input [n_vocab, n_rows] f32. Per row i1 the op
  writes (max logit, argmax index as float) at elements [0, 1] of the result
  row; elements [2, ne[0]) are never written. Each device executes the op
  over its own shard, so the pair is that shard's (max, LOCAL argmax).
- Meta: one case in the split-state switch ->
  handle_generic(src_ss, /*scalar_only =*/ false). The output inherits the
  input partition; the ratio block recomputes per-die ne = shard_j (ratio
  n_vocab/n_vocab = 1). No cross-shard op, no SPLIT_AXIS_UNKNOWN, no
  handle_per_row.
- Fetch: ggml-backend-meta's get_tensor / get_tensor_async gain a
  single-shard sub-row path (ggml_backend_meta_subrow_shard): a byte range
  inside one shard's slice of a single row maps to that device's simple
  tensor (row * shard_stride + within-row offset). Row-aligned and
  cross-shard ranges keep the existing paths, so every existing caller is
  unchanged (today sub-row ranges hit row-alignment asserts). decode()
  fetches 2 floats per shard and row: 24 B in 3 tiny DMAs instead of one
  517 KB splice; the copies enqueue on each owning die's compute
  stream via get_tensor_async (stream-ordered after the graph).
- Shard offsets: new API ggml_backend_meta_tensor_split_offsets(tensor,
  offsets, n_max) returns the per-device element offsets along the split
  axis (unsplit/replicated tensors report one shard at 0). Resolved once at
  the first fetch, cached in llama_context.
- Host merge: common_shard_argmax_pick(pairs, n_pairs, &logit) - strict max
  over the pair values, first pair wins ties. Shards are ordered by
  ascending vocab index and each device already picks the lowest LOCAL
  index, so the merge is exactly the lowest-index argmax of the spliced row
  (every index in shard d precedes every index in shard d+1). decode()
  resolves local to global indices once per decode (generation-guarded) so
  the accessor hands out ready (max, global idx) pairs.
- Accessor: llama_get_shard_argmax_ith(ctx, idx, &n_shards), no-sync like
  the packed fetch (caller drains); llama-context resolves rows via
  output_ids. Staging lives in buf_output next to the logits blob
  (2*n_shards floats per row, backend-count upper bound at reserve time).
- Skip: when the graph carries the node, decode() skips the raw-logits row
  fetch entirely. The h_nextn rows are untouched (draft inputs still stream
  host-side); target verify rows are untouched (the node exists only in
  graph_mtp: qwen35, qwen35moe, step35, cohere2moe, one build_shard_argmax()
  call each, gated on cparams.draft_ondevice_argmax).

Kernel: ggml-cpu ops.cpp + ggml-cuda/shard-argmax.cu (grid = rows, block
reduce with lexicographic (val, idx) comparator, lowest index wins ties,
writes 2 floats per row). Note the pre-existing ggml argmax kernels select
unspecified ids on exact ties; this op pins lowest-index.

## 2. Gate

LLAMA_DRAFT_ONDEVICE_ARGMAX=1. Unset: no graph node, no fetch change, no
buffer change - byte-identical. Set: draft loop merges the pairs into
data[0] = {argmax id, max logit, p=0.0f} - identical shape to the current
non-packed candidates (p is 0 on every host path today), so the p_min gate
behaves identically. A failed pair fetch stops the draft round loudly
(SPC_ERR) instead of falling back to the skipped logits buffer. Mutually
exclusive with LLAMA_DRAFT_PACKED_GET in the spec ctor (that lever would
re-fetch the full rows; a warning fires if both are set).

## 3. Tie-break honesty (proof scope)

"Identical to the host argmax" is proven for DISTINCT logits, where the max
is unique and every path must agree. On EXACT ties the current host paths
are themselves unspecified and mutually inconsistent (g++ probe + the
predecessor's E-054 note: std::partial_sort and the heap-select give
different tied ids, e.g. 17 vs 3 for ties beyond k, 1 vs 5 within k). The
on-device path is MORE deterministic: lowest global index, and the host test
pins merge == lowest-index argmax on ties (within shard, across shards,
all-equal, boundary). This is the same documented divergence class FAST_TOPK
banked - greedy rounds with distinct logits (the real-model case) are
byte-identical.

## 4. Host tests

docs/amd-port/tests/test_onsample_argmax_host.cpp (ggml-linked, runs the
REAL op through ggml_backend_cpu over emulated per-die slabs, no GPU):

- crafted ties across all 3 shards {5,3,4}: merge picks id 2 (lowest global),
  per-shard local argmaxes 2/1/3 verified from device output
- single shard == plain argmax
- uneven 3-way shards at 129272: {43091,43091,43090}, {40000,60000,29272},
  {60000,40000,29272}, {29272,29272,70728}, 2 rows each, merge ==
  lowest-index argmax and == both host sampler path mirrors (distinct)
- full-scale ties: within-shard, cross-shard, all-3-shard, boundary-straddling
  and all-equal maxima - merge == lowest-index argmax
- 1-ULP near-ties at the k boundary
- staging lifetime: merge reads only the 2*n_shards packet (poisoned tail
  ignored), stale packet copies stay valid across a simulated decode that
  overwrites the staging, new decode reads through
- fetch mapping: sub-row pairs land on the owning shard with packed-stride
  offsets, second row included; whole-row and cross-shard ranges rejected

Result: ALL PASS. test_mtp_sampling_host.cpp re-run: ALL PASS (regression).

## 6. Served-arm spec (coordinator window, no boots run by this desk)

- Arm A (baseline): campaign config as of HEAD, no new env.
- Arm B: campaign config + LLAMA_DRAFT_ONDEVICE_ARGMAX=1.
- Greedy gate: identical drafted-token sequences vs Arm A round by round
  (accept 0.66667 class must hold); any drift = tie-class divergence, log it.
- Attribution: + LLAMA_SPEC_TIMELINE=1 LLAMA_DECODE_TIMELINE=1 - the pair
  path deletes the 517 KB D2H + full-row drain share of the per-step sample
  window; expected effect is modest (ms/round class) - the strategic value
  is deleting the draft loop's host row round trips, the prerequisite for
  step-batching.
- Do NOT combine with LLAMA_DRAFT_PACKED_GET (ctor disables it with a
  warning). LLAMA_DRAFT_FAST_TOPK is irrelevant under this gate (the pairs
  branch short-circuits before the sampler paths).
