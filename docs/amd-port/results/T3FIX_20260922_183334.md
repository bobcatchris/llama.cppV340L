## 1. Root cause (E-087 defect, proven)

The copy-back registration sized the D2D copy as the FULL 2-D area:

    cb.nbytes = members[m]->src[0]->ne[1] * members[m]->ne[0] * sizeof(float);

but a T=1 mmvq result is ONE float per weight row: the pool temp holds
exactly row_high - row_low floats (the grouped kernel writes dst[row] for
row in [0, nrows_x), mmvq.cu:744), and the member dst is ne[0] floats. For
mul_mat, dst ne[0] == src0 ne[1], so the computed count was ne[0]-times
oversized (Kcur-3: 256 rows x ne[0] 256 x 4 B = 256 KiB copied from a
~1 KiB pool block into a 1 KiB dst).

Consequences by mode, both now explained:

- PREFILL (eager): the oversized copies happened to stay inside the
  allocation ranges (pool first-fit handed the temp a big recycled block),
  so HIP raised nothing and the corruption of the 255/256 tail + neighbors
  went unnoticed - "prefill ran fine" in E-087.
- DECODE (first graph, capture): the hipMemcpyAsync at ggml-cuda.cu:5108
  crossed out-of-allocation ranges and HIP rejected the call itself:
  "ROCm error: invalid argument" - exactly E-087's abort.

EMPIRICAL PROOF (hipcc gfx900 capture matrix, /tmp/t3_diag/capture_diag.hip,
idle die 0 under the boot lock): legal-size D2D hipMemcpyAsync captures,
instantiates, replays x2 and verifies MATCH on HIP 6.2.41133 / gfx900:xnack-
(cases 3/5/6); oversized count returns invalid argument AT THE CALL, eager
and captured alike (cases 2/4). The three briefed hypotheses are excluded:
(a) temp address instability - first-capture abort, and pool temps are
capture-stable by the same invariant the solo path's captured scratch uses;
(b) legacy/default stream - ctx.stream() is a created stream and case 3
captures fine on it; (c) cross-device D2D - both pointers live on ctx.device
(the exec-side guard enforces it). The API form was legal; the SIZE was not.

## 2. Fix (one line, ggml-cuda.cu)

    cb.nbytes = ggml_nbytes(members[m]);

(the member's full result; equals row_diff * sizeof(float) here). The
memcpy form itself is kept - capture legality is proven above. Host test
test_t3_detect_host: ALL PASS after the change (detection logic untouched).

members execute capture- and replay-safely, results byte-exact, decode
