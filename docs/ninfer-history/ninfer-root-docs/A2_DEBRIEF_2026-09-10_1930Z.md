## THE FIX DESIGN (committed, 57bfb8a6 + 8197edc9 + 91c5eaab)

**(c) consume-at-producer / piecewise stash-consume** — zero VRAM, no contract change:
```
cap = prefix_cache_capacity (16384)
for (poff = 0; poff < plen; poff += cap):
    piece = min(cap, plen - poff)
    copy cached_ph[0..piece] ← prefill_dummy[piece_off..+piece]   // stash THIS piece
    ph = cached_ph.slice(1, 0, piece)
    for (off = poff; off < poff+piece; off += mpc):                // existing pattern
        mtp_forward_batch(mtp_ids.slice(0,off,len), ph.slice(1, off-poff, len),
                          mtp_pos.slice(0,off,len), Envelope{1,off+len}, mh_scratch, ...)
    // seed = mh_scratch last column (track last_len; final piece wins)
```
Read/write windows disjoint per piece; no plen ceiling; zero extra VRAM. Patch preserved: `drafts/167_piecewise_attempt.patch` (85 lines, applies to b52a0ecc-era tree). The v1 attempt crashed at 30k because the STASH SOURCE (prefill_dummy[16384..]) does not exist — the piece must be consumed BEFORE moving past cap_cols, which the design above does (per-piece copy-then-consume). **The v1 crash was a design-order bug in the attempt, not a disproof of (c).**
