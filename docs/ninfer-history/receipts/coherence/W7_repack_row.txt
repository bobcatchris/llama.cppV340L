CROSS-LINE CROSS-VALIDATION (coordinator notice, cited): Team Green's PRMT decode atom
  (NVIDIA side) measured +8.2% kernel / +3.2% serve with the explicit law "a shared-memory
  LUT losing does NOT condemn table lookup — PRMT is a table without memory". Same mechanism
  class as this desk's v_perm register-LUT (V arm = PRMT-shaped decode on GCN5): both lines
  confirm the register-resident LUT wins while a memory-backed LUT path loses (their
  shared-LUT NO-GO -7..-14%; our V0 baseline carries exactly such an LDS LUT, and the V arm
  deletes it).

WHY the win is bounded (mechanism, for the next desk): V deletes the 128-body LDS table reads
  and most waitcnts (212 -> 32) but at TN=64 the grid doubles in y and the tile is smaller;
  the mad-mix insight (decode stream = the scheduler's latency-hiding material) still prices
  the floor: V keeps MAC density (pk16-class) and buys ~1.14x, not the 1.5x+ the op-count
  delta alone would suggest. The GEMM-front ledger context stands: this is an AMBER lever on
  a front the pk16 row already closed at the 2.0x bar.

DEBUG RECEIPTS (the bench caught 3 RED kernels before any GREEN number was believed —
  relL2 1.46e+02 class would have been the pk16 failure repeated):
  run1: V relL2 3.54e-01, exactly-half bitdiff -> --debug mode (per-group coeff values 1..4)
    named the loss arithmetically (V = V0 x 0.25 then 0.75 then 1.0 as bugs closed):
    1. word-split masks were swapped: (pE<<8)&0x00FF00FF zeroes 3 of 4 lanes (pE<<8 puts
       h2 at byte2, not byte3) -> exactly 1/4 of products; correct = (pE&0x00FF00FF)<<8.
    2. x restage q1/q3 put BOTH lanes in the high half ((p0&0xFFFF0000)|((p2&0xFFFF)<<16)
       = [0, k1|k4]) -> 0.75; correct = (p0>>16)|(p2&0xFFFF0000).
    3. token domain: reader indexed s_x by GLOBAL token (tok0+t) while the stage writes
       BLOCK-LOCAL 0..TN-1 — at grid.y=1 that is out-of-bounds LDS (the zero half). V0 never
       hits this (TN=128 covers all M so local==global); any TN<M port must re-derive it.
  Uniform-data trap: memset patterns (0x11 codes / 0x3C x) make every permutation
  value-preserving, which HID bugs 2-3 partially — the per-group-coeff --debug mode and the
  rel-L2 gate are what exposed them. Keep both in any future decode-swap desk.
